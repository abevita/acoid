PACKAGE CONTRACT
==================================================

Purpose:
- provide a reusable Go package for generating and validating ACOID values
- support deterministic code generation for any consuming Go project
- keep the generation flow identical across libraries, services, CLIs, and applications

Canonical flow:
1. take input bytes 
2. hash input with BLAKE3
3. convert hash output into ID57 characters
4. project to the requested length
5. return the final ACOID string

Supported lengths only:
- 6
- 8
- 10
- 12

Out of scope:
- storage adapters
- HTTP/API boundary behavior
- persistence collision handling
- project-specific entity mappings

==================================================
SOURCE OF TRUTH
==================================================

Primary package rules:
- alphabet: ID57
- generator: BLAKE3
- output type: ACOID string
- supported lengths: 6, 8, 10, 12 only

ID57 alphabet:
ABCDEFGHJKLMNPQRSTUVWXYZ
abcdefghijkmnpqrstuvwxyz
123456789

Removed characters:
- 0
- o
- O
- I
- l

Package invariants:
- same input + same length MUST produce the same ACOID
- different supported lengths MAY produce different outputs for the same input
- unsupported lengths MUST return an error
- output MUST contain only ID57 characters
- output MUST match the requested supported length exactly

STORY 1
==================================================

Card
--------------------------------------------------
As a Go developer,
I want a deterministic generator function,
so that the same input always yields the same ACOID for a chosen supported length.

Conversation
--------------------------------------------------
Scope:
- hash arbitrary input bytes with BLAKE3
- convert digest material into ID57 characters
- return a string of the requested supported length

Questions already resolved by the package contract:
- generation flow is fixed: BLAKE3 -> ACOID(length)
- generation is deterministic, not random
- only lengths 6, 8, 10, and 12 are supported

Suggested API surface:
- Generate(input []byte, length int) (string, error)
- MustGenerate(input []byte, length int) string

Confirmation
--------------------------------------------------
1. Given the same input and length 6, when Generate is called twice, then both results are identical.
2. Given the same input and length 8, when Generate is called twice, then both results are identical.
3. Given the same input and length 10, when Generate is called twice, then both results are identical.
4. Given the same input and length 12, when Generate is called twice, then both results are identical.
5. Given different inputs and the same length, when Generate is called, then the outputs differ in normal operation.
6. Given any generated output, when inspected, then every character belongs to the ID57 alphabet.

- Independent: yes
- Valuable: yes
- Small: yes
- Testable: yes

==================================================
SPIKE 1
==================================================

Card
--------------------------------------------------
As a package maintainer,
I want to choose and document the exact digest-to-ID57 projection algorithm,
so that all consumers get byte-for-byte identical ACOID outputs.

Conversation
--------------------------------------------------
Decision needed:
- how BLAKE3 digest bytes are projected into ID57 characters
- whether projection uses modulo mapping, big-integer base conversion, or another fixed method
- how additional digest material is derived if more characters are needed than one digest projection conveniently supplies
  - Note: BLAKE3 supports variable-length output (XOF mode); requesting exactly the required byte count may eliminate multi-round derivation
- output must be deterministic
- output must use only ID57 characters
- output length must be exactly one of 6, 8, 10, 12
- algorithm must be documented clearly enough for reimplementation if needed

Time-box: 0.5 day review.

Output:
- one documented projection algorithm
- one reference example with stable input and output
- package documentation updated to describe the algorithm at a high level

Confirmation
--------------------------------------------------
1. A written decision exists describing the digest-to-ACOID projection algorithm.
2. A stable example input produces a stable example output.
3. Different Go projects using the same package version receive identical results.
